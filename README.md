# DDE — Discovery of Differential Equations

Исследовательский проект по **автоматическому обнаружению дифференциальных
уравнений и аналитических законов по наблюдательным данным**.

Задача проекта — восстановить выражение вида

```text
F(x, x_dot, x_ddot, ...) = 0
```

по наборам траекторий или временных рядов. В отличие от SINDy, проект не
ограничивается разреженным поиском в заранее заданной библиотеке функций.
В отличие от PINN, поиск структуры не основан на регуляризации посредством
дифференциального физического потерь.

В репозитории реализована архитектура **Graph-Based Equation Editor (GBEE)**.
Остальные подходы из [исходного документа `t1.pdf`](t1.pdf) описаны как
исследовательские гипотезы и в настоящей версии не реализованы.

## Цель и постановка задачи

Для набора наблюдений `D = {t, x(t), ...}` необходимо найти структурно
корректное выражение с минимальной невязкой на данных:

```text
F(x, x_dot, x_ddot, ...) = 0
```

Гипотеза проекта состоит в том, что латентные представления и различные формы
представления уравнения позволяют моделировать структуру закона напрямую,
вместо перебора фиксированного набора базисных функций.

## Исследовательские гипотезы

Ниже приведены все пять архитектур из [`t1.pdf`](t1.pdf).

### 1. Интегральный генеративный автоэнкодер (I-GAE)

**Идея:** вместо численного дифференцирования зашумленных траекторий модель
должна генерировать и проверять интегральную форму уравнения.

Вариационный автоэнкодер кодирует набор траекторий `D` в латентное
представление:

```text
z ~ q_phi(z | D)
```

Символический декодер на основе attention генерирует структуру уравнения,
связанную с интегральной невязкой:

```text
integral[t0, t] f(x(tau), x_dot(tau), ...) d_tau = 0
```

**Ожидаемое преимущество:** интегрирование действует как естественный
низкочастотный фильтр и снижает чувствительность к шуму в производных.

**Статус:** концептуальная архитектура. Реализация отсутствует.

### 2. Π-размерностный трансформер

**Идея:** использовать теорему Бакингема до или в процессе обучения, чтобы
ограничивать поиск физически допустимыми комбинациями величин.

На вход модели передаются физические переменные вместе с векторами размерностей,
например:

```text
[L, M, T, ...]
```

Attention-механизм оценивает взаимодействия переменных и формирует
безразмерные группы:

```text
pi1, pi2, ..., pin
```

Декодер строит уравнение вида:

```text
Phi(pi1, pi2, ..., pin) = 0
```

**Ожидаемое преимущество:** физически недопустимые комбинации исключаются
ещё до поиска символической структуры.

**Статус:** концептуальная архитектура. Реализация отсутствует.

### 3. Символический рекуррентный автоэнкодер (S-RAE)

**Идея:** извлечь латентную динамику временного ряда и рекуррентно декодировать
последовательность символов дифференциального закона.

Предлагаемый конвейер:

1. CNN или Transformer извлекает признаки временного ряда.
2. RNN или LSTM моделирует скрытую динамику `h_t`.
3. Seq2Seq-декодер переводит скрытое состояние в токены операторов,
   переменных и констант.
4. Токены собираются в аналитическое выражение.

**Ожидаемое преимущество:** латентная динамика может отражать сложные
зависимости, которые не описываются простым фиксированным полиномиальным
набором базисных функций.

**Статус:** концептуальная архитектура. Реализация отсутствует.

### 4. Графовый нейронный редактор уравнений (GBEE)

**Идея:** представлять уравнение как expression graph или DAG, а поиск вести
путём атомарных правок графа.

- узлы описывают переменные, константы и операторы;
- рёбра связывают аргументы с операторами;
- позиция аргумента сохраняет порядок операндов;
- GNN предсказывает добавление или удаление ребра;
- mutation может заменять тип узла;
- качество кандидата оценивается невязкой уравнения на данных.

Ключевое достоинство подхода — гибкое изменение топологии без полной
перегенерации всей структуры уравнения. Невалидные состояния могут
отфильтровывать маски допустимых действий.

**Статус:** частично реализованная архитектура в каталоге
[`gbee_project/`](gbee_project/).

### 5. Ансамблевый бустинг редукторов

**Идея:** объединить несколько слабых сетей-редакторов символических
структур в ансамбль с последовательным исправлением ошибок.

Разные слабые редакторы могут специализироваться на отдельных семействах
функций:

- тригонометрических;
- экспоненциальных;
- полиномиальных;
- иных операторных группах.

Каждый следующий редактор должен добавлять компоненты или изменять
структуру так, чтобы уменьшать невязку ансамбля. Постепенное усложнение
уравнения может снизить переобучение на шуме.

**Статус:** концептуальная архитектура. Реализация отсутствует.

## Реализованная версия: GBEE

Текущий модуль [`gbee_project/`](gbee_project/) реализует графовый редактор
уравнений с гиперограниченной грамматикой. Он использует:

- неизменяемые DAG выражений;
- точную оценку операторов;
- атомарные действия `mutate`, `rewire`, `wrap`, `collapse` и `stop`;
- маски допустимых переходов;
- MPNN на базе PyTorch Geometric;
- SciPy-оптимизацию обучаемых констант;
- on-policy REINFORCE;
- отдельный ограниченный beam search.

Непрерывные константы подбираются после изменения дискретной топологии.
Кандидат оценивается по MSE обучающих наблюдений и штрафу за сложность.

## Быстрый запуск

Требуется Python 3.10 или новее.

```bash
git clone https://github.com/Makovyova/DDE.git
cd DDE/gbee_project

python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[dev]"
```

Запуск синтетического примера:

```bash
python -m examples.demo --epochs 40 --seed 7
```

Демо генерирует целевое выражение:

```text
2.5 * x1 + sin(x2)
```

По 128 обучающим точкам обучается поиск графа. Отдельная выборка из
1024 точек используется только для финальной проверки.

Запуск без beam search:

```bash
python -m examples.demo --epochs 120 --seed 7 --beam-width 0
```

Расширенный словарь операторов:

```bash
python -m examples.demo \
  --operators "+" "*" "-" "/" "sin" "exp" \
  --epochs 300
```

## Пример Python API

```python
import numpy as np
import torch

from gbee import (
    ActionSpace,
    ConstantOptimizer,
    EditorNetwork,
    ExpressionDAG,
    HybridEnvironment,
    MaskedEditorPolicy,
    Node,
    ReinforceTrainer,
    TrainConfig,
)

torch.manual_seed(7)
rng = np.random.default_rng(7)

X = rng.uniform(-2, 2, size=(128, 2))
y = 2.5 * X[:, 0] + np.sin(X[:, 1])

initial = ExpressionDAG.build([Node.variable(0)], root=0)
actions = ActionSpace(
    n_variables=2,
    max_nodes=9,
    max_constants=3,
    operators=("+", "*", "sin"),
)

policy = MaskedEditorPolicy(
    EditorNetwork(2, hidden_dim=48, num_layers=2),
    actions,
)
environment = HybridEnvironment(
    X,
    y,
    ConstantOptimizer(method="BFGS", maxiter=40),
    complexity_weight=1e-3,
)
trainer = ReinforceTrainer(
    policy,
    environment,
    initial,
    TrainConfig(
        epochs=40,
        episodes_per_batch=16,
        horizon=5,
        seed=7,
    ),
)

result = trainer.train()
print(result.best.graph.to_expression(12))
print(result.best.mse)
```

Для пользовательских данных `X` должен содержать столько столбцов, сколько
входных переменных объявлено в `n_variables`. Вектор `y` должен иметь форму
`(n_samples,)` или `(n_samples, 1)`.

Тесты проверяют DAG, арность операторов, позиционные рёбра, hash-consing,

## Ограничения

Текущая реализация ограничена:

- малым символическим словарём операторов;
- локальной оптимизацией констант;
- стохастическим обучением policy;
- ограниченным размером и глубиной графа;
- отсутствием динамической фазовой переменной в общем DDЕ-конвейере.

Методы I-GAE, Π-трансформер, S-RAE и ансамблевый бустинг пока являются
исследовательскими гипотезами и требуют отдельных реализаций и экспериментов.
